## 1. Principles

1. **One scientific protocol, localized surfaces.** The interview logic, stage cards, rubric, and schema exist once. Only what people read is localized: interface strings, probe phrasings, templates, documentation.
2. **Codes, not words, in data.** Every enumeration in the [schema](../../schemas/README.md) is a language-neutral code; display labels come from locale files.
3. **Originals are sacred.** Each free-text statement is stored in the language in which it was written or spoken, and that original is never replaced. Translations are additional versions labelled with `machine_translated`, `translation_of`, `translator`, and a timestamp.
4. **Controlled terminology.** An English–Chinese glossary of econometric terms anchors the interviewer's vocabulary and the translations, and is reviewed by bilingual economists.
5. **Extensibility.** Languages are identified by BCP 47 tags (`en`, `zh-Hans`); adding a language means adding locale files, glossary entries, and reviewed probe phrasings — never changing the protocol or the schema.

## 2. What is localized, and how

| Content | Localization strategy | Who produces it | Review |

| Interview probes | Probe library: one identifier, phrasings per language ([protocol §8](../interview/expert-interview-protocol.md#8-probe-library)) | Protocol authors | Bilingual economist |
| Live interview conversation | Generated by the model in the contributor's chosen language, instructed to use glossary terms | Model | Contributor (during the interview); spot checks |
| Scientific terminology | Glossary (appendix) | Project team | Bilingual economists |
| Validation feedback | Message codes rendered through localized templates | Developers | Bilingual review |
| Contribution summaries | Generated from the schema in the contributor's language; an English working translation is added, labelled as machine-generated, for reviewers | Model, from schema data | Contributor reviews their-language version; optionally the translation |
| Export and submission instructions | Localized templates | Project team | Bilingual review |
| Agent-facing task instructions | English for the first release (proposed; see §5) | Shepherd and contributor | Benchmark reviewer |

## 3. Behaviour in the interview

- **Choosing a language.** At S0, with the choice stored in session state and in the record (`languages.interview`). The contributor can switch at any time; each turn records its language.
- **Code-switching is normal.** Chinese-speaking economists often use English technical terms inside Chinese sentences. The interviewer accepts this and mirrors the contributor's usage. On first use of a technical term in Chinese, it gives the English term in parentheses, e.g., 交错双重差分（staggered DiD）.
- **Quoting the contributor.** Summaries quote the contributor's own words where precision matters, rather than paraphrasing them through translation.
- **Translations for reviewers.** Reviewers who do not read Chinese see a labelled English working translation next to the original. Disputed meaning is resolved against the original, with the contributor if necessary.

## 4. Architecture-specific implementation

### Option A — hosted platform

- **Framework (proposed):** `next-intl` (current 4.x) for a Next.js stack, with ICU MessageFormat and locale-prefixed routes (`/en/...`, `/zh/...`). Use Lingui instead if translators work in standard translation-management tools [P-page, R9].
- **Language switcher** on every page; the choice is remembered per account and per browser.
- **Fonts:** a CJK-capable stack using system fonts (PingFang SC, Microsoft YaHei, Noto Sans CJK) or self-hosted subsets. A single full Noto Sans SC file is 17.8 MB [P-page]. Whether third-party font services are reachable from mainland China is contested [S], so do not depend on them.
- **Server-side:** the model's system prompt is assembled from the same protocol assets, with a locale parameter selecting probe phrasings and templates; the glossary is injected as reference material.

### Option B — local Claude Code skill

- **Model-facing instructions stay in English, in one place.** `SKILL.md` and the stage cards are not duplicated per language; they instruct the model to converse in the selected language and to follow the glossary.
- **User-facing assets are per language:** `locales/en/` and `locales/zh-Hans/` hold templates (summaries, consent text, export instructions) and probe phrasings.
- **Language selection:** asked at the start of the skill, stored in the local session state, and reused on resume. Claude Code has a documented `language` setting, but a plugin cannot set it. The workspace sets it, and the skill also states the language explicitly [P-page, R2].
- **Helper scripts** (state, validation, packaging) print messages from small message catalogs.
- **Documentation:** `README.md` and `README.zh-Hans.md`; installation guides in both languages.

## 5. Open questions

1. **Language of agent-facing tasks.** Proposed: English for the first release, so that scores measure economics capability rather than language ability. Chinese-language task variants could be a later, separately reported extension.
2. **Translation of contributor statements.** Should the contributor review the English working translation of their own statements (more burden, higher fidelity), or only the original (less burden)? Proposed: optional review, mandatory only for statements quoted in agent-facing or published material.
3. **Glossary authority.** Who approves terminology when Chinese usage varies (e.g., 双重差分 vs 倍差法)? Proposed: two bilingual economists, with a recorded rationale.
